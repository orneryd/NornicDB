## Owner families

- **count-publication**: publish a committed or applied write's node and relationship counts to the engine totals, after the write is visible
- **cypher-count-reads**: Cypher reads totals of the executor's (namespaced) engine: count fast paths, planner statistics, db.info and SHOW DATABASE
- **derived-counts**: maintain the derived label, relationship-type and positional counts: append deltas in the writing commit, apply staged deltas, fold deltas into their base at open, Close, restore and in the background
- **engine-entity-writes**: the engine's direct entity writers count their own write in the same Badger commit, ordered by the write-order owner
- **lifecycle**: set or remove whole totals: at open (initializeCounts), at Close, and for a deleted prefix
- **quota-accounting**: multidb keeps each database's stored-byte usage: the size-tracking engine charges the writes it forwards, the manager applies the deltas and recomputes them when dirty
- **quota-checks**: multidb's limit checks read the database's own usage, scoped by database name
- **storage-count-readers**: the engine's count API and its scoping wrappers (namespaced, composite, WAL): each reads the totals of the namespace or store it serves
- **transaction-staging**: a transaction stages its count deltas and discards them when it closes; its commit applies them with its writes
- **write-behind-buffer**: a generation records the count delta of the commits it acknowledges, published when it is applied
- **write-order**: the entity write order, the lifecycle write and the drained write (with the sidecar commit run under it): every write passes them after the acknowledged commits it must follow
