# Security triage

## Streaming PostExecute context omission

The non-tool streaming action route omitted the request context from PostExecute hooks. Accepted callbacks consequently lost request principal/database-scope values and session-memory writes were refused. The correction passes the existing context, preserving cancellation detachment and permission checks. Public-handler regression tests cover both route aliases, authenticated and authentication-disabled requests, and denied/unattributed requests. This is an availability/context-propagation finding; no authorization bypass is established. The analogous PreExecute omission is also corrected and covered through the same fixture, with request values retained and callback cancellation detachment preserved.

## Imported schema durability

Public native export/import followed by close/reopen loses imported constraints, property indexes and policy definitions while retaining token metadata. The in-memory schema replacement is not durably published. The correction prepares and validates a detached definition, persists it through the configured namespace owner, then publishes all schema families and the compiled policy table. Integrated native reopen, rejected-write, invalid-binding, canceled-admission and healthy-retry race controls pass (storage 5.916s, adminimport 4.014s). Direct invalid definition loads also preserve the previous complete schema. Full combined release verification remains pending. Potential integrity implications still require triage; exploitability has not been established.

## Graph projection cancellation

`CALL gds.graph.project` discarded its statement context before streaming nodes
and relationships. Controlled public requests canceled during a large projection
continued building and left the projection in the catalog. This can extend
resource use beyond a canceled request; severity and exploitability require
triage. No authorization bypass or cross-database exposure is established.

The correction forwards the originating context through the registered handler
and both population streams, preserves cancellation errors, and checks again
before catalog publication. Deterministic component controls cover cancellation
at a delivered node/relationship and after a successful final stream. Public
node-heavy/edge-heavy public cancellation and deterministic component controls
pass together under the race detector (69.885s), measuring from actual cancellation
to return. The frozen release gate remains pending. Earlier delay-based timing
estimates are not an exact cancel-to-retirement measurement. Per release policy, versions below 1.4.4 are
presumed affected for triage; the earliest affected implementation has not been
established. No advisory has been published from this finding.

## Transaction memory override inheritance

Server database configuration registered inherited process values as explicit database limits. This could leave later process limits unenforced, retain a removed override, or freeze the other setting when only one database override was configured. Adding/removing an override equal to its inherited value also skipped runtime application. These are resource-limit enforcement defects in configurations that change defaults or overrides; no unauthenticated configuration write or independent authorization bypass is established. The correction preserves explicit presence independently for each limit, keeps zero as explicitly unlimited, and retains live pool usage and running-statement ceilings. Public HTTP configuration/query regression controls cover inheritance, removal, partial overrides and equal-value presence changes; final integrated release verification remains required.

## Accepted deferred visibility action cancellation (PR #1693 API migration)

Public Execute reproductions confirmed that a graph commit could succeed while cancellation rejected its queued `kp.suppress` action, leaving the entity visible. The initial correction covered statement-phase contexts; independent plain-request controls also reproduced the defect, covering callers without that phase owner. The canonical `transactionWAL.finishCommitted` completion now retains request values while dropping cancellation authority only after callers confirm native commit. Pre-acceptance cancellation remains rejected.

Both implicit and explicit public Execute controls, healthy retry, and durable suppression after reopen pass with statement-phase and plain cancellable contexts (normal 1.593s; race 4.444s). These are public execution and commit-boundary tests, not a dedicated HTTP/Bolt wire reproduction. Final integrated census and full `make test` remain pending. This is a visibility correctness defect; an independent authentication or authorization bypass has not been established. No advisory was published for this unmerged migration defect.

## Registered procedure write-effect classification

NOR-300 current-release probes on `f45b1a51a` show that QueryAnalyzer and the
CALL keyword helper classify registered WRITE `kp.suppress` calls as reads,
while the execution contract correctly identifies the write. Separate controls
show query analysis treating mutation keywords inside literals or property
names as writes. These are reproduced classification discrepancies affecting
cache/planning consumers; the probes do not establish stale-cache corruption,
an authorization bypass, or cross-database exposure. Existing permission checks
also consult the execution contract and registered procedure modes.

The correction must use one effect owner, preserve READ/WRITE permissions,
refresh decisions on procedure-registry changes, and qualify public cache and
transaction behavior. The historical assumption that versions below 1.4.4 are
affected is a triage policy, not evidence of the earliest affected commit.
Severity and any advisory requirement remain pending demonstrated user impact.

The authorization schema-command list omitted TEXT, POINT and LOOKUP forms
present in the ordinary schema-DDL owner. Public Execute controls confirmed
accepted catalog changes under a read/write permission checker that denied
schema permission. LOOKUP controls prepared a catalog without its default lookup
rule; TEXT and POINT controls required no such setup. The correction reuses
isOrdinarySchemaDDL and the integrated authorization/metadata controls pass.
HTTP/Bolt socket qualification and historical release boundaries remain pending;
no broader data-access or data-loss result is claimed.
