### 3. Cause — why the earlier corrections left holes

**The missing owner is the compiled graph-expression contract: its original language form, persistent/current scope, required values and execution demand.** The runtime manifestation is a missing shared execution frame, including retention through the body and strategy selection over that same frame. There are several matching kernels, which is valid; there are also several independent interpretations of what names/values they may match, which is not.

- r1 removed the executor-local matcher, but made ordinary bound-hop predicates pay the generic EXISTS wrapper's parsing/executor/row setup. It also gave a plain pattern the existential local-binding policy. The intended semantic boundary and the execution route were conflated.
- r2 introduced a graph-free cached predicate plan and restored the direct hop. It retained the split: variable validation accepts `fabricRecordBindings`, the predicate's value check reads only `compiledRowScope`, and other fast kernels receive only their supplied row. The generic executor merges outer bindings later. Thus strategy selection happens **before** effective scope resolution.
- The larger runtime defect is not confined to the predicate's null check. `correlatedSubqueryExecutor` populates `fabricRecordBindings` and `executePipeline` seeds the first row from it, but internal WITH plans retain `pipelineImports(ctx)`, which the CALL owner installs. The expression-subquery entry does not install the same persistent-import frame. The static walk retains expression imports (`subqueryScope.visible` / `carryStaticSubqueryImports`), while runtime projection can remove them. MATCH can consequently bind a new local, a comprehension can scan the graph, or a later CALL cannot find a statically valid import. Merging values only inside `patternPredicatePlan.evaluate` cannot correct these members.
- Release expresses this same split with `pipelineRowOutput.carried` and rewritten WITH projections, rather than develop's context-based import carrier. The scope policy must converge in both implementations; copying only the predicate evaluator or assuming the develop helper exists on release would leave another hole.
- Entity-only adapters compound this by equating an omitted entity with a bound null. A null import must constrain a match to no path; an absent name inside a local-binding form may be introduced. Those states cannot be recovered after dropping nil entries.
- Pre-validation normalisation is another causal entry, not just a runtime adapter: `desugarLabelExpressions` converts a predicate with Boolean labels/types into a local-binding existential body before the scope walk. The original form's pre-bound-name restriction has been erased. The new undefined-`b` oracle failures prove that merely sharing the final matcher does not preserve the source language contract.
- Two context branches also synthesize EXISTS independently (I08), and the test-only legacy matcher remains a separate implementation. Runtime coverage reaches the `pattern_expression.go` rewrite; the `functions_eval_functions.go` fallback is structurally present but not reached by this population. The previous statement that all predicate execution had one owner was too narrow.
- Row production is also part of the contract. `pipelineNodePredicateProperties` relies on `semanticExpressionReferences`; that scanner skips names followed by `:`, so an inline node pattern can require properties that the scan projection did not request. Passing a correctly named but incomplete node still makes the owner return a wrong answer. The endpoint-map WITH * attack demonstrates this separate input-representation hole.
- The performance correction used the result wrapper's `first` flag to skip degree selection, although **first match still materialises the whole chosen adjacency**. `boundTraversalCount` likewise expands general paths before filtering bound endpoints. Other wrappers use optional/traversal kernels and different retention. The cost/accounting decision is distributed across strategy routes rather than following the matched working set.

The previous verification varied pattern syntax and outer expression positions but did not systematically cross persistent imports and body horizons with strategy/output/consumer. It predominantly exercised successful direct comprehensions or their SIZE form, not their full projection with another imported expression. The one-edge benchmark could not detect dense-end materialisation. The generated attack closes those verification gaps and exposes stored-data consequences.

### 4. Plan — one mechanism for the complete causal unit

This is a proposal for gate review, **not permission inferred to resume implementation**.

1. **One compiled graph-expression plan and one execution entry.** Capture a plain predicate, comprehension and EXISTS/COUNT/COLLECT in a form-tagged plan with syntax, free/local bindings, required entity/property reads, output demand and safe strategy admissions. Capture the original form and its binding contract **before** label/type/quantified-path normalisation. The normaliser must preserve/use that plan's contract when lowering a predicate, rather than silently replacing its admission policy with existential-local semantics. Cached plans contain syntax/dependencies, never an executor, database or row value. Compile the reusable body/strategy once, retaining the fixed-hop kernel within this owner.
2. **Resolve one frame before choosing any strategy.** The frame retains name presence separately from value, including null, and separates persistent expression imports, current locals, CALL imports, parameters and internal context keys. Current values shadow imports where the language/retained extension permits it. Use develop's existing `carrySubqueryImports` retention rule for both static visibility and runtime horizons; adapt release's `carried`/WITH-rewrite mechanism to this same owner policy within the integrated change, not a new merge rule in each evaluator or a wholesale backport of unrelated pipeline work. Preserve the current transaction/storage view and error context in the frame.
3. **Carry that frame through the whole body.** Expression imports must remain visible after every WITH/aggregation/DISTINCT horizon, through every UNION branch and until a genuine CALL boundary selects its own import set. MATCH and comprehensions consume the retained row, so they cannot silently rebind a disappeared import. Generic execution gets this same frame; remove the independent MATCH/id/WITH import reconstruction from `executeCorrelatedSubqueryBody` in favour of frame-aware execution. Keep the shared UNION combiner and CALL clause executor as genuine clause/protocol boundaries.
4. **Converge the consumers.** `patternPredicatePlan`, row/context predicate adapters, row subquery/value programs, comprehension adapters, the EXISTS-synthesising normaliser/context branches and the legacy helper consume that same contract/entry. `boundDegreeCount`, bound hop/chain/node kernels, optional matching and generic pipeline remain execution mechanisms beneath it; none invents a scope or treats an unavailable binding as a local. Comprehension path shadowing and projection scope are selected by the same plan/frame. Fabric's record adapter supplies this frame through its existing graph/transaction protocol; its batch/projection decisions cannot reinterpret a nested graph expression.
5. **Make producer requirements part of the same plan.** Label-scan/property/header projection reads the compiled graph expression's binding/property requirements. An inline node-map read and a `b.key` read must request the same needed value. Do not repair this with another independent pattern scanner or by loading a node after an earlier strategy has already used an incomplete binding.
6. **One expansion/resource decision for equivalent matching demand.** Choose the smaller safe bound endpoint for existence, counting and projected rows, independent of the wrapper name. Preserve direction, relationship identity, labels/maps, path uniqueness and variable-length semantics when reversing or declining an optimisation. Keep compiled fixed-hop matching; make equivalent `*1..1` and generic fallback behaviour explicit. Charge the actual retained adjacency/path/row buffers across the selected kernel, including combined-adjacency/header capabilities, before keeping them. Memory-budget success alone is not the accounting proof.
7. **Verify the integrated unit through every mapped consumer.** Retain the current-head failing evidence, add durable generated scope/strategy/consumer families, and rerun every matrix member on both parsers and all three routes on the integrated heads. Add assertions for returned values **and stored graph effects**, actual parameters, null-vs-absent, full comprehension projections, UNION/CALL and WITH grouping. Use accurate capability probes and requested-byte/budget checks for the resource population, plus transaction/live-as-of/cancellation controls. Preserve #1384's existing suites and differential families; run the previously requested focused and full `pkg/cypher` checks on both target heads after the gate approves implementation.
8. **Optimise and measure, without an invented threshold.** Queue paired A/B with `ab --no-wait` in normal order; never hold/move/remove anyone else's jobs. Compare the final bound-hop path and relevant controls, optimise the integrated implementation, and state any remaining time/allocation cost, cause and limit plainly in the PR. The maintainer decides whether an unavoidable measured cost is acceptable. The gate itself does not submit a new benchmark of unchanged code.

The in-scope unit is graph-expression semantics and its current consumers. DDL existence, property-only existence, GDS/text/date pattern functions and unrelated parser/transaction features stay outside it. Existing intentional extensions are recorded and preserved unless an established Cypher contract or the operator decides otherwise. No PR is marked ready based on this analysis. The next action is the orchestrator's review of this inventory/cause/plan, not another leaf correction.
