## Findings

### P2 — both PRs: a surviving outer binding becomes false after an internal `WITH`

`pkg/cypher/pattern_predicate.go:55` accepts a variable found in `fabricRecordBindings`, but `patternPredicatePlan.evaluate` then reads only `scope.lookup` at `pkg/cypher/pattern_predicate.go:72`. When an EXISTS body's `WITH` removes the imported value from its current row, the owner mistakes that absent row entry for a bound null and returns false without consulting the surviving outer binding.

Repro after creating `(:ReviewA {id:1})-[:T]->(:ReviewB)`:

```cypher
MATCH (a:ReviewA {id:1})
RETURN EXISTS {
  WITH 1 AS k
  MATCH (b:ReviewB)
  WHERE (a)-[:T]->(b)
}
```

Neo4j 5.26.30 returns `true`: `bash sig/tnrun.sh cypher neo-ref sig/handoff/reviews/daybreak-1468-1459r2-oracle-imported-binding.cypher`, job `j20261018104614-75880-fd62`.

- #1468 returns `false` on both parsers, job `i20261018064838-64172-d9cc`; its current develop base returns `true`, `i20261018065108-73304-59a6`.
- #1459 returns `false` on both parsers, job `i20261018064952-90444-784d`; the original #1459 head `f418585d4` returns `true`, `i20261018065426-67092-ea8c`. The release base already returns false, so the combined release PR loses a correction made by its #1384 portion rather than regressing the branch base.
- The RC composition also returns false, `i20261018065333-82756-36c9`.

### P2 — #1468: bound EXISTS abandons the sparse endpoint and can fail a previously sufficient transaction budget

`pkg/cypher/subquery_value_expression.go:720` now chooses the lower-degree endpoint only when `!first`. Pattern predicates call it with `first=true`, so a bound `Hub -> Target` EXISTS always materializes the hub's outgoing adjacency even when the target has one incoming edge.

## Neo4j scope semantics

Independent shell probes confirm Neo4j **5.26.30**:

- Pattern comprehensions, `EXISTS {}` and `COUNT {}` may introduce local node and relationship variables; OPTIONAL MATCH introduces nullable variables. Bound dynamic label/type expressions work, while static label/type names remain schema tokens. Valid matrix: `j20261018104029-92532-d21c`.
- A plain WHERE pattern cannot introduce a named node or relationship: `j20261018104050-92440-f550`, `j20261018104111-61816-5311`.
- `exists(pattern)` and an OPTIONAL MATCH's WHERE pattern obey the same rule: `j20261018103946-62592-6109`, `j20261018104007-60952-951b`.

- Comprehension/EXISTS/COUNT locals do not escape their expression: `j20261018103821-67908-791a`, `j20261018103925-25200-a1ab`, `j20261018103843-21020-5475`.
