**Graph precision limit:** this is a structural aid, not a sound Go type analysis. The tool reports a real direct `.Close -> .closeInternal` path, but no directed path onward to cross-file `closeOwnedEmbedders`, despite the explicit source call. It also misresolves `embedQueue.Close()` at db_lifecycle82 to DB.Close and `timer.Stop()` to Server.Stop. Broad Close/Stop query seeds include test and Python symbols and are truncated; those are not accepted as real callers. Every claimed provider route/caller in this inventory was therefore reconciled with the complete rg selector population, receiver/source inspection and probes; absence of a Graphify path is never used as evidence of no consumer. Interface callbacks, closures and generation aliases need that reconciliation. No Graphify implementation was modified to hide these limits.

### 3. Cause: the owner that is missing

The previous corrections never defined one transition system from **reserve construction / acquire resource generation / admit DB operation / cancel / drain actual work / release / publish completion**. They each made one local wait look like the resource lifetime. The split is concrete: server.closed/initCancel/initDone, DB.closed/buildCancel/bgWg/foregroundWg, the provider publication binding and per-DB registry, ownedEmbedders/resource.once, EmbedWorker.ctx/wg plus uncounted child goroutines, Search.Service relationship workers, and native.mu/warmupStarted/closeOnce all independently decide part of shutdown. A boolean means both “stop admission” and “cleanup finished”; context.Canceled means both shutdown and ordinary request failure; wrapper type means both capability and ownership identity. None of those equivalences is valid.

| Correction | Local boundary used | Why the next hole survived |
| --- | --- | --- |
| Original/r1 | Join server/DB initializer before shutdown; reject late SetEmbedder | Owned the goroutine but not every constructed model. A failed-health object had no explicit release transition; inherited leak survived |
| r1 follow-up/r2 | Release unsuccessful constructed models; then own every accepted model in a DB list | Successful publication did not transfer a proved lifetime for its users/aliases. Queue worker completion was treated as native model completion; healthy installed leak was initially invisible, then provider list still omitted foreground users |
| r2 follow-up/r3 | Close all owned providers after queue/bgWg; fix native warmup join | Listed resources, but did not establish what “all users joined” means. Direct foreground calls still used providers during release; native Close newly exercised a never-started warmup channel |
| r3 follow-up/r4 | Add a whole-Execute foreground lease and derived cancellation context; wait foregroundWg; track native warmupStarted | The lexical Execute includes application callbacks and ordinary queries that never use a provider. Thus self-join/deadlock and allocations. Other transports lease only provider calls, so post-embedding work falls outside lifetime. A second Close sees closed=true before completion. Shutdown identity is erased into ordinary embedding failure before fallback/error adapters |
| New inventory evidence | Same split, beyond r4's examples | Queue inference children, search-owned relationship workers, raw returned handles and traced aliases all bypass a different part. Fixing only the four review examples would leave demonstrated unsafe release/leak/race paths |

The causal unit is therefore **DB resource activity and completion**, with provider generations as resources and server shutdown as a requester/task owner. It is not an individual transport handler, foreground WaitGroup or provider Close method. Merely adding more waits, special cases for a callback, or another FatalEmbeddingError predicate would repeat the failed treatment. The inventory adds a second callback class, a second worker owner, wrapper-dependent release and a post-provider storage race; these require the ownership boundary to change.

### 4. Plan: one lifecycle owner, no implementation yet

Use one DB lifecycle owner as the only writer of phase, resource-generation ownership, active operation/task membership and completion result. A small serialized transition reducer under one mutex is sufficient; no dedicated goroutine per query is required. An atomic phase/counter fast path can expose admission without allocating per-call objects, but it must implement the same owner transitions, not become a second source of truth. Resource-internal locks still protect provider internals; they do not independently decide DB lifecycle.

Proposed global phases: **Open -> Quiescing -> Draining -> Releasing -> Closed(done, error)**. Admission seals once. Cancellation carries a stable DB-shutdown cause. Draining waits for the actual last provider/native/DB-resource use, not a parent wrapper that abandoned a goroutine. Release happens after that proof. All concurrent/repeated DB.Close callers await the same done channel and observe the persisted result. Startup-failure cleanup enters this same owner. A context-limited Server.Stop may return a deadline error while its registered shutdown remains incomplete; it must not report nil completion because another caller started Stop.

1. **Construction and ownership publication.** Reserve a constructor task before launching it. Register a constructed resource before health checks, even if construction returns both an object and error. One resource-generation record owns health/retry/install/retire/release transitions. Publication and admission are coupled to that record. Per-DB singleflight, discarded factories, refused late publication and global/default aliases all use it; cancellation and release share one result rather than independent lists/flags.
2. **Managed resource handles and identity.** Publish a managed generation handle, preserving typed/query/document/property/batch/chunker/metadata semantics. DB-returned handles, snapshots, method values, scoped executor bindings, cache/tracing aliases and worker captures resolve to the same resource identity. Provider capability wrappers must not change release identity or hide Close. Replacements retire the old generation while its users hold it. Cache hits/no-provider/supplied-vector/ID paths still pass the operation's phase check; absence of inference cannot mean “DB remains open.” Do not take ownership of unrelated external model objects that never transferred into DB.
3. **Actual activity, including child tasks and search storage.** Count a provider call before spawning its child and decrement only when the call actually returns. Queue cancel/timeout cannot detach activity from its owner. Node and relationship workers, lazy per-DB constructors, warmup integration and post-embedding search/storage work are registered in the same draining order. Search service workers must be registered and joined before their model is released; current relationship workers have cancellation but no join. Shutdown cancellation is not an embedding outage eligible for BM25 fallback. Request activity and native provider activity are distinct records under the same owner, so neither an uncounted request nor a released native model slips through.
4. **Callback boundary, rather than goroutine-ID detection.** Explicitly end/suspend the caller's owned DB-operation segment before invoking an application-controlled synchronous result/queue callback; before any subsequent owned DB work, resume only through owner admission. A callback may call Close because its own DB/provider/storage work is quiescent; Close is not defined as waiting for user callback completion. Move queue notifications out of a joined worker region under the same rule. No goroutine-ID heuristic, detached Close success, timeout pretending completion or provider release during a still-active caller. The inventory's result-stream and queue callback sites both need this integrated boundary; dropping only a provider lease is insufficient to protect storage.
5. **Server and protocol integration.** Server init/request/transport groups register with the owner. Server.Stop joins its own registered tasks for every caller; it retains the established distinction between stopping a server and closing a potentially shared DB. Consumer adapters receive one shutdown/unavailable identity from the shared search/execution owner. HTTP uses the established503 unavailable response; gRPC maps to Canceled/Unavailable as appropriate; Bolt/MCP/Heimdall preserve a failed/canceled result. Ordinary external embedding failures can keep documented keyword fallback. Centralize shutdown recognition before the shared fallback decision, with transport-specific encoding only at protocol boundaries.
6. **Allocation and component shutdown.** Ordinary admission uses existing statement/request state or a value token and atomic/mutex accounting; no unconditional WithCancel/AfterFunc/closure allocation per ordinary query. Attach cancellation lazily only for actual cancellable work. Native warmup joins only a worker that was started and does not hold the worker's required lock while joining. Keep prior r1/r2/r3 properties and release-error visibility. Paired TrueNAS `ab --no-wait` benchmarks must report query allocations/time and startup/shutdown time against the release baseline; **there is no5% threshold**. Optimize, explain remaining measured cost and leave its acceptance to the maintainer.
