## Approved Rule 73 plan and cause

The user explicitly **APPROVED the Rule 73 gate and section 4**, then restricted implementation to develop/1.5.0, then parked it. The complete mechanical inventory, extraction commands, Graphify cross-check, public-path self-attacks and causal analysis are in [rc144-r73-analysis-section.md](rc144-r73-analysis-section.md) and [rc144-final-2.md](rc144-final-2.md), under **Rule 73 family analysis**. Review reports r1–r4 are preserved in [evidence](park-1.5.0-1469/evidence). The source inventory was obtained mechanically with recorded `rg` selectors plus local Graphify; it was not reconstructed from review findings.

The causal failure is split ownership: server Stop/init flags, DB closed/cancel/wait groups, publication binding, provider list, queue parent versus inference children, relationship workers, wrappers and native shutdown independently decide parts of admission/cancellation/drain/release/completion. Each earlier fix proved only a local join. r1 joined initialization but did not release failed-health resources; r2 owned resources without owning every actual consumer; r3 joined workers while foreground/native work could still run; r4 counted lexical queries, including synchronous application callbacks, while other transports continued storage work outside the provider lease. The flags also confused "closing" with "complete", cancellation with an ordinary model outage, and wrapper capability with ownership identity.

Resume the **whole causal unit**, not individual findings:

1. One DB owner and one transition reducer write phase, resource generations, activity and final result: `Open -> Quiescing -> Draining -> Releasing -> Closed(done,error)`. Atomic phase views are observations of that reducer, not a second authority. Every concurrent Close observes the same persisted completion/error. No goroutine-ID tricks, detached success, or timeout that pretends completion.
2. Register construction before launch and resources before health checks. Publication, rejection, failed health, retry, replacement, per-DB singleflight, cached/traced aliases and release use one identity/generation record. Managed handles preserve the source's optional typed/document/property/batch/metadata capabilities.
3. Count actual provider calls before child launch until actual return; include request storage work, relationship work, queue children and lazy construction. Server groups belong to the same owner but Server.Stop retains its existing contract of stopping that server without releasing a shared DB.
4. Explicitly suspend the caller's owned operation segment and synchronous ancestor chain at application callbacks, then resume only through admission. Independent native calls stay counted. Close must not join the callback's own quiescent segment, and execution must not resume DB work after a closing callback.
5. Propagate one shutdown identity before keyword fallback. HTTP 503, native gRPC Canceled/Unavailable, Qdrant not Internal, Bolt/MCP/Heimdall failed/canceled. Ordinary embedding failures still get the documented keyword fallback. Guard nil/cache/vector/ID paths and retained handles too.
6. Reuse statement/request state for allocation-free ordinary admission; attach cancellable I/O lazily. Native warmup joins only a worker actually started. Optimize and measure paired query time/allocations plus startup/shutdown with `ab --no-wait`; **there is no percentage threshold**. State remaining measured cost plainly for the maintainer. The existing uncorrected head measured 31 versus 26 allocations per ordinary query; no claim is made that the provisional draft removes them.
